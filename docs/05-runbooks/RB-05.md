# RB-05 - Network Partition Between Regions

## 1. Scenario Identification
**ID:** S5 | **Category:** Infrastructure | **Severity:** P1-Critical | **Components:** Transit Gateway, VPN/PrivateLink, routes, replication, both application regions.

## 2. Detection Mechanism
Page when cross-region packet loss exceeds 2%, probes fail for 60 seconds, or replication lag exceeds 60 seconds while both regional APIs remain healthy.

## 3. Impact Assessment
A three-minute split brain at 1,200 TPS creates an upper bound of 216,000 ambiguous requests. Keep one writer authoritative and quantify duplicate and unknown transactions by idempotency key.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P1 and freeze deployments.
2. **Network (20s):** Run `aws ec2 describe-transit-gateway-attachments --region ap-south-1`.
3. **Network (20s):** Run `aws ec2 describe-route-tables --region ap-south-1`.
4. **SRE (20s):** Run `kubectl -n paysecure get pods` in both contexts.
5. **DBA (30s):** Stop any uncontrolled secondary writes and record writer ownership.

## 5. Diagnostic Steps (2-5 minutes)
6. **Network (20s):** Run `Test-NetConnection $env:DR_PRIVATE_ENDPOINT -Port 443`.
7. **Network (20s):** Run `aws ec2 describe-network-acls --region ap-south-1`.
8. **DBA (30s):** Run `aws rds describe-global-clusters --global-cluster-identifier $env:PAYSECURE_GLOBAL_CLUSTER_ID`.
9. **SRE (20s):** Compare API and Route 53 health in each region.
10. **IC (20s):** If Mumbai is unhealthy, invoke RB-01; if both APIs are healthy but replication is broken, fence Hyderabad; if both write, declare split brain and stop both settlement writers.

## 6. Failover Procedure (5-15 minutes)
11. **Network (30s):** Confirm routes and attachment state with `aws ec2 describe-transit-gateway-attachments --region ap-south-2`.
12. **Platform (30s):** Scale the non-authoritative region's payment deployment to zero with `kubectl -n paysecure scale deployment/payment-api --replicas=0`.
13. **DBA (30s):** Confirm one Aurora writer and pause settlement in the fenced region.
14. **App lead (45s):** Reconcile the idempotency table and event log before reopening writes.
15. **IC (30s):** Resume traffic only after packet loss is below 1%, replication is healthy, and duplicate exposure is accepted and recorded.

## 7. Communication Protocol
Engineering receives partition scope and writer state. Management receives the 216,000-request upper bound and actual unknown count. Merchants are told to retain original idempotency keys. Regulators receive impact, duration, and reconciliation status if financial duplication or loss occurred.

## 8. Verification and Validation
Cross-region TCP probes pass; `aws rds describe-global-clusters` shows one writer; duplicate-key query returns no unresolved duplicates; both API health checks pass; settlement queue drains without duplicate payouts.

## 9. Rollback Procedure
If fencing worsens impact, keep the original authoritative writer, restore the previous deployment scale, and remove only the approved route change. Do not merge datasets until DBA and reconciliation owners sign off.

## 10. Post-Incident Review
Build a timeline from network flow logs and CloudTrail, quantify unknown and duplicate requests, perform five-whys, and update fencing and partition drills.
