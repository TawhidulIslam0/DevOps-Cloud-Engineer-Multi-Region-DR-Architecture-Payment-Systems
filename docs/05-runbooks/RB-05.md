# RB-05 — Network Partition

## 1. Scenario Identification

**Runbook ID:** RB-05  
**Scenario:** Network Partition  
**Category:** Infrastructure  
**Severity:** P1 — Critical

### Affected Components

- Amazon VPC
- EKS worker nodes
- EKS pods
- Application Load Balancers
- Transit Gateway
- Partner bank VPN connections
- Corporate network connectivity
- MSK Kafka
- Aurora PostgreSQL
- DynamoDB
- ElastiCache Redis
- AWS PrivateLink endpoints
- Route 53
- Network Load Balancer / internal load-balancing paths
- Security groups
- Network ACLs
- Application services
- Monitoring and observability systems

### Scenario Description

A network partition causes one or more PaySecure application components, Availability Zones, or regions to lose connectivity with other required components.

The failure may occur between:

- EKS and MSK
- EKS and Aurora
- EKS and DynamoDB
- EKS and ElastiCache
- PaySecure and partner banks
- PaySecure and the corporate network
- Mumbai and Hyderabad
- Application clients and ALBs

A network partition can create partial service failure rather than a complete regional outage. This makes diagnosis particularly important because some components may remain healthy while dependent services become unreachable.

Potential causes include:

- VPC routing failure
- Transit Gateway failure
- VPN tunnel failure
- Network ACL misconfiguration
- Security group changes
- Availability Zone network failure
- AWS regional networking failure
- DNS resolution failure
- PrivateLink endpoint failure
- Cross-region connectivity failure
- Route propagation failure

### Recovery Objectives

- **Target RTO:** < 5 minutes
- **Target RPO:** < 1 minute
- **Primary Region:** Mumbai (`ap-south-1`)
- **Recovery Region:** Hyderabad (`ap-south-2`)

## 2. Detection Mechanism

### Primary Detection Signals

| Signal | Threshold | Severity |
|---|---:|---|
| Application connectivity failures | >5% for 2 minutes | P1 |
| Network packet loss | >2% sustained | P1 |
| API 5xx errors | >5% for 2 minutes | P1 |
| EKS node NotReady count | >0 in affected AZ | P1 |
| MSK connection failures | >5% | P1 |
| Aurora connection failures | >5% | P1 |
| Redis connection failures | >5% | P1 |
| Partner VPN tunnel down | Any critical partner tunnel | P1 |
| Transit Gateway packet loss | Sustained abnormal level | P1 |
| Cross-region connectivity | Failed health probes | P1 |
