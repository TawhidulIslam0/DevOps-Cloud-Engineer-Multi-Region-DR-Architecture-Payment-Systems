## 1. Scenario Identification

### Scenario

The NPCI/UPI payment network experiences a nationwide or widespread outage
while PaySecure's AWS infrastructure remains operational.

This scenario is an **external dependency failure**, not automatically an
AWS or PaySecure infrastructure failure.

The project brief requires this runbook to address:

- External versus internal failure distinction
- Merchant communication
- Alternative payment methods
- Transaction queuing for retry
- NPCI restoration monitoring
- Post-outage reconciliation

### Affected Components

Potentially affected:

- Payment API
- UPI payment adapter
- Partner bank integrations
- EKS payment microservices
- Aurora PostgreSQL
- DynamoDB
- ElastiCache Redis
- MSK Kafka
- Merchant-facing APIs
- Webhook delivery service
- Monitoring and alerting

The following are expected to remain operational if the outage is external:

- EKS
- Aurora
- DynamoDB
- Redis
- MSK
- ALB
- WAF
- Route 53
- Internal APIs

## 2. Detection Mechanism

### Primary Indicators

Trigger investigation when several of the following occur:

```text
UPI transaction failure rate > 20%
UPI timeout rate > 10%
UPI response latency P95 > 10 seconds
Multiple merchants report UPI failures
Non-UPI payment methods remain healthy
PaySecure infrastructure metrics remain normal
