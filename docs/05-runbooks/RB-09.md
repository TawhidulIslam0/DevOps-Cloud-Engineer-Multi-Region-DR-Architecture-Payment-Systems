# RB-09 - Certificate Expiry or TLS Failure

## 1. Scenario Identification
**ID:** S9 | **Category:** Infrastructure | **Severity:** P2-High | **Components:** ACM, ALB listeners, DNS validation, API clients, certificates.

## 2. Detection Mechanism
Alert at 30, 14, 7, and 1 day before expiry, or immediately on TLS handshake failures and hostname mismatch.

## 3. Impact Assessment
All HTTPS API clients may fail. Record affected domain, client population, payment method, and unknown in-flight requests; do not retry unknown payments without the original idempotency key.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P1/P2 based on client impact and freeze certificate changes.
2. **SRE (20s):** Run `aws acm list-certificates --region ap-south-1`.
3. **SRE (20s):** Run `openssl s_client -connect api.paysecure.example:443 -servername api.paysecure.example`.
4. **Network (20s):** Run `aws elbv2 describe-listeners --load-balancer-arn $env:PAYSECURE_ALB_ARN --region ap-south-1`.
5. **App lead (30s):** Preserve idempotency and communicate degraded TLS status.

## 5. Diagnostic Steps (2-5 minutes)
6. **Security (20s):** Run `aws acm describe-certificate --certificate-arn $env:PAYSECURE_CERT_ARN --region ap-south-1`.
7. **Network (20s):** Run `aws elbv2 describe-listener-certificates --listener-arn $env:PAYSECURE_LISTENER_ARN --region ap-south-1`.
8. **SRE (20s):** Test from at least two client TLS stacks.
9. **DNS (20s):** Verify ACM DNS validation records with `Resolve-DnsName`.
10. **IC (20s):** If certificate is valid but one client fails, use compatibility testing; if expired/mismatched, renew/import; if ALB is unhealthy, invoke RB-01.

## 6. Failover Procedure (5-15 minutes)
11. **Security (60s):** Request/validate replacement with `aws acm request-certificate --domain-name api.paysecure.example --validation-method DNS --region ap-south-1`.
12. **DNS (30s):** Apply validation records with `aws route53 change-resource-record-sets --hosted-zone-id $env:PAYSECURE_HOSTED_ZONE_ID --change-batch file://acm-validation.json`.
13. **Security (60s):** Wait for `aws acm wait certificate-validated --certificate-arn $env:PAYSECURE_NEW_CERT_ARN --region ap-south-1`.
14. **Network (30s):** Attach with `aws elbv2 add-listener-certificates --listener-arn $env:PAYSECURE_LISTENER_ARN --certificates CertificateArn=$env:PAYSECURE_NEW_CERT_ARN --region ap-south-1`.
15. **SRE (30s):** Repeat TLS and synthetic tests before removing the old certificate.

## 7. Communication Protocol
Notify engineering, management, merchants, and regulators when the outage is material. Include domain, client impact, certificate status, ETA, and next update time.

## 8. Verification and Validation
TLS chain, hostname, expiry, ALB listener, browser/client compatibility, API health, and synthetic idempotent transaction all pass.

## 9. Rollback Procedure
Keep the old certificate attached until validation passes. If the new certificate fails, remove only the new listener association and restore the prior certificate with `aws elbv2 add-listener-certificates`.

## 10. Post-Incident Review
Review expiry alerts, ACM validation, listener changes, client testing, and automation gaps; assign owners.
