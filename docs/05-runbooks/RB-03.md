# RB-03 - DNS Poisoning or DNS Infrastructure Failure

## 1. Scenario Identification
**ID:** S3 | **Category:** Security/Infrastructure | **Severity:** P1-Critical | **Components:** Route 53, DNSSEC, ALB, WAF, TLS, CloudTrail, GuardDuty. Target RTO: 5 minutes.

## 2. Detection Mechanism
Page on DNSSEC validation failure, an unauthorized answer, Route 53 health failure, or API 5xx above 5% for 2 minutes. Confirm from three external resolvers before changing records.

## 3. Impact Assessment
Unauthorised DNS can expose 45,000 merchants and redirect payment traffic. Freeze payment writes if the destination is untrusted; estimate impact from failed requests and record evidence for CERT-In.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P1, freeze DNS changes and deployments.
2. **Security (20s):** Preserve resolver answers with `Resolve-DnsName api.paysecure.example -Type A`.
3. **SRE (20s):** Run `aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=ChangeResourceRecordSets --max-results 20`.
4. **Network (20s):** Run `aws route53 list-hosted-zones-by-name --dns-name paysecure.example`.
5. **App lead (30s):** Disable non-idempotent retries and protect unknown transactions.

## 5. Diagnostic Steps (2-5 minutes)
6. **Security (20s):** Compare answers from `nslookup api.paysecure.example 1.1.1.1` and `nslookup api.paysecure.example 8.8.8.8`.
7. **Network (20s):** Run `aws route53 get-hosted-zone --id $env:PAYSECURE_HOSTED_ZONE_ID`.
8. **Security (30s):** Run `aws route53 list-resource-record-sets --hosted-zone-id $env:PAYSECURE_HOSTED_ZONE_ID`.
9. **SRE (20s):** Test `curl --fail-with-body https://api.paysecure.example/health/ready`.
10. **IC (20s):** If only one resolver is wrong, investigate poisoning; if Route 53 and all resolvers agree on a wrong record, treat as account compromise; if DNS is correct but API fails, invoke RB-01/RB-12.

## 6. Failover Procedure (5-15 minutes)
11. **Security (30s):** Disable the suspected IAM principal with `aws iam put-user-policy` or the approved break-glass control; preserve CloudTrail first.
12. **Network (45s):** Apply the signed known-good batch with `aws route53 change-resource-record-sets --hosted-zone-id $env:PAYSECURE_HOSTED_ZONE_ID --change-batch file://dns-known-good.json`.
13. **Network (30s):** Wait using `aws route53 wait resource-record-sets-changed --id $env:PAYSECURE_ROUTE53_CHANGE_ID`.
14. **Security (30s):** Confirm DNSSEC and certificate identity from independent resolvers.
15. **IC (30s):** If DNS remains untrusted, route critical partners through the approved alternate provider and contact AWS Support/CERT-In; do not accept payment traffic at an unknown IP.

## 7. Communication Protocol
Engineering: `[P1][S3][{id}] DNS integrity incident; current answer {ip}; action {action}; next update {time}`. Management: `{status}, merchant impact {count}, security exposure {scope}, ETA {time}`. Merchants: `Do not retry unknown transactions; trusted endpoint recovery is {status}`. Regulators: include detection time, records affected, containment, evidence, and CISO contact.

## 8. Verification and Validation
`Resolve-DnsName` must match approved ALB addresses from three resolvers; `curl` must return 200; `aws cloudtrail lookup-events` must show only approved changes; TLS hostname and DNSSEC validation must pass; synthetic idempotent transaction must create one event.

## 9. Rollback Procedure
If the signed batch is wrong, apply the prior signed JSON, wait for INSYNC, and re-run all resolver and TLS checks. Keep payment writes disabled if any resolver or certificate check fails.

## 10. Post-Incident Review
Within 2 business days preserve CloudTrail, resolver, DNSSEC, WAF, and certificate evidence; perform five-whys; rotate exposed credentials; document CERT-In/RBI/PCI checks and corrective owners.
