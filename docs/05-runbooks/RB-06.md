# RB-06 - Cryptographic Key Compromise

## 1. Scenario Identification
**ID:** S6 | **Category:** Security | **Severity:** P1-Critical | **Components:** KMS, Secrets Manager, Aurora, S3, EKS, PCI CDE. Target containment: 5 minutes.

## 2. Detection Mechanism
Page on anomalous KMS usage above 3x baseline, GuardDuty high finding, unauthorized grant, or confirmed key exposure.

## 3. Impact Assessment
Cardholder and transaction data may be exposed. Freeze affected writes, preserve audit evidence, identify key versions and data classes, and estimate affected records before notifying PCI, RBI, card networks, or CERT-In.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open security P1 and invoke the CISO.
2. **Security (20s):** Run `aws kms describe-key --key-id $env:PAYSECURE_KMS_KEY_ID --region ap-south-1`.
3. **Security (20s):** Run `aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventSource,AttributeValue=kms.amazonaws.com --max-results 50`.
4. **IAM (30s):** Disable the suspected principal and revoke the suspected grant with `aws kms revoke-grant --key-id $env:PAYSECURE_KMS_KEY_ID --grant-id $env:PAYSECURE_GRANT_ID`.
5. **App lead (30s):** Stop affected payment writes and prevent replication of known compromised plaintext.

## 5. Diagnostic Steps (2-5 minutes)
6. **Security (20s):** Run `aws kms list-key-policies --key-id $env:PAYSECURE_KMS_KEY_ID --region ap-south-1`.
7. **Security (20s):** Run `aws kms list-grants --key-id $env:PAYSECURE_KMS_KEY_ID --region ap-south-1`.
8. **Platform (20s):** Run `kubectl -n paysecure get secrets` and record access without printing values.
9. **DBA (30s):** Identify encrypted stores and last known clean backup.
10. **IC (20s):** If key compromise is unconfirmed, preserve and investigate; if confirmed but data is intact, rotate and re-encrypt; if plaintext exposure is confirmed, isolate both regions and invoke trusted rebuild.

## 6. Failover Procedure (5-15 minutes)
11. **KMS owner (30s):** Create a replacement key with `aws kms create-key --description PaySecure-emergency-replacement --region ap-south-1`.
12. **KMS owner (30s):** Enable rotation with `aws kms enable-key-rotation --key-id $env:PAYSECURE_NEW_KEY_ID`.
13. **Secrets owner (30s):** Rotate affected secrets with `aws secretsmanager rotate-secret --secret-id $env:PAYSECURE_SECRET_ID --region ap-south-1`.
14. **Platform (30s):** Roll workloads to the new key reference using `kubectl -n paysecure rollout restart deployment/payment-api`.
15. **CISO (30s):** Approve re-encryption and notifications only after clean-key access tests pass; record PCI 72-hour notification decision.

## 7. Communication Protocol
Security engineering receives containment status. Management receives data-class scope and customer risk. Merchants receive only approved service-impact language. CISO sends PCI, RBI, CERT-In, and card-network notices when the legal decision tree requires them.

## 8. Verification and Validation
CloudTrail shows no unauthorized new use; new key encrypt/decrypt test passes; `kubectl rollout status` succeeds; affected stores can decrypt with the replacement key; old-key access is denied; clean backup restore is validated.

## 9. Rollback Procedure
Do not re-enable the compromised key. If the replacement rollout fails, isolate workloads and restore only from a verified clean backup under the replacement key. Preserve forensic copies and require CISO approval before reopening writes.

## 10. Post-Incident Review
Complete evidence chain, key/grant timeline, affected-data inventory, PCI/RBI/CERT-In decisions, five-whys, and hardening actions.
