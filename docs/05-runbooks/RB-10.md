# RB-10 — Data Centre Power Failure (Single AZ)

**Runbook ID:** RB-10  
**Scenario:** Data Centre Power Failure (Single AZ)  
**Category:** Infrastructure  
**Severity:** P1-Critical  
**Primary Region:** ap-south-1 (Mumbai)  
**DR Region:** ap-south-2 (Hyderabad)  
**Target RTO:** <5 minutes  
**Target RPO:** <1 minute  
**Owner:** Incident Commander / Platform Engineering  
**Last Reviewed:** September 2026

---

## 1. Scenario Identification

### Scenario

A single Availability Zone (AZ) within the Mumbai region experiences a
major infrastructure or power failure.

PaySecure is designed across three Availability Zones in ap-south-1.
The expected response is therefore to isolate the affected AZ and continue
serving traffic from healthy AZs.

A single-AZ failure does not automatically require regional failover.

Regional failover should only be considered when healthy capacity in Mumbai
is insufficient or when the failure expands beyond a single AZ.

### Affected Components

Potentially affected:

- EKS worker nodes
- EKS pods
- Application Load Balancer targets
- Kubernetes services
- Aurora instances
- MSK brokers
- ElastiCache nodes
- NAT gateways
- Private subnets
- Transit Gateway connectivity
- Availability Zone-specific infrastructure
- Monitoring and logging

## 2. Detection Mechanism

### Primary Indicators

Trigger investigation when one AZ shows multiple simultaneous failures:

```text
EKS nodes NotReady in one AZ
ALB healthy targets decrease sharply
Pod availability decreases
EC2 instance reachability failures
AZ-specific packet loss
Application 5xx rate >5%
Application P95 latency >5 seconds
Aurora instance failure
MSK broker failure
ElastiCache node failure
