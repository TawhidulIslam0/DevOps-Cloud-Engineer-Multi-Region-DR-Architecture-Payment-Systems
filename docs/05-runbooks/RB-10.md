# RB-10 - Single Availability Zone Power Failure

## 1. Scenario Identification
**ID:** S10 | **Category:** Infrastructure | **Severity:** P2-High | **Components:** one AZ, EKS nodes, Aurora reader, two MSK brokers, ALB targets.

## 2. Detection Mechanism
Page when more than two EKS nodes are unready for 3 minutes, ALB target health falls below 90%, or AZ-specific MSK/Aurora alarms fire.

## 3. Impact Assessment
Approximately one third of compute capacity, one database replica, and two brokers may be lost. Confirm remaining capacity for 1,200 TPS before regional failover.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P2 and freeze capacity changes.
2. **SRE (20s):** Run `kubectl get nodes -o wide`.
3. **SRE (20s):** Run `aws ec2 describe-instances --filters Name=availability-zone,Values=$env:FAILED_AZ --region ap-south-1`.
4. **DBA (20s):** Run `aws rds describe-db-clusters --db-cluster-identifier $env:PAYSECURE_DB_CLUSTER_ID --region ap-south-1`.
5. **Data engineer (30s):** Check MSK broker and partition health.

## 5. Diagnostic Steps (2-5 minutes)
6. **Platform (20s):** Run `kubectl get pods -n paysecure -o wide`.
7. **Network (20s):** Run `aws elbv2 describe-target-health --target-group-arn $env:PAYSECURE_TARGET_GROUP_ARN --region ap-south-1`.
8. **SRE (20s):** Run `aws eks describe-nodegroup --cluster-name $env:PAYSECURE_CLUSTER --nodegroup-name $env:PAYSECURE_NODEGROUP --region ap-south-1`.
9. **DBA (20s):** Check writer and reader status.
10. **IC (20s):** If remaining capacity supports 1,200 TPS, stay in Mumbai; if capacity is below peak or outage spreads, invoke RB-01; if only replication link fails, invoke RB-05.

## 6. Failover Procedure (5-15 minutes)
11. **Platform (30s):** Cordon failed nodes with `kubectl cordon $env:FAILED_NODES`.
12. **Platform (30s):** Scale node group with `aws eks update-nodegroup-config --cluster-name $env:PAYSECURE_CLUSTER --nodegroup-name $env:PAYSECURE_NODEGROUP --scaling-config minSize=24,maxSize=36,desiredSize=24 --region ap-south-1`.
13. **DBA (30s):** Verify Aurora automatic failover completed.
14. **Data engineer (30s):** Confirm MSK under-replicated partitions are zero.
15. **IC (30s):** Reopen capacity only after ALB, EKS, Aurora, MSK, and synthetic checks pass.

## 7. Communication Protocol
Engineering gets AZ and capacity status. Management gets remaining TPS capacity. Merchants receive a degradation notice only if payment success falls. Regulators are notified if uptime/SLA thresholds are breached.

## 8. Verification and Validation
Nodes are ready, ALB targets healthy, Aurora writer available, MSK partitions replicated, P99 below 300 ms, and synthetic payment passes.

## 9. Rollback Procedure
Remove cordon only after node health is confirmed, restore prior desired capacity after stabilization, and cancel regional failover if no spread occurred.

## 10. Post-Incident Review
Review AZ impact, rescheduling, capacity headroom, AWS event evidence, and corrective actions.
