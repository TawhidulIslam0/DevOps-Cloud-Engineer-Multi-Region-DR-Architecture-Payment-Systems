## 1. Scenario Identification

### Scenario

PaySecure's public payment API experiences a severe distributed denial-of-service
attack.

Normal payment API traffic is approximately **1,200 TPS**, but observed traffic
increases to **150,000+ requests per second**.

The project brief requires this runbook to address:

- DDoS classification
- WAF rate limiting
- AWS Shield Advanced engagement
- Traffic engineering
- Merchant communication
- Post-attack analysis

### Affected Components

- Internet-facing payment API
- Application Load Balancer
- AWS WAF
- EKS payment microservices
- EKS ingress
- Fraud detection service
- Aurora PostgreSQL
- DynamoDB
- ElastiCache Redis
- MSK Kafka
- Route 53
- CloudWatch
- Prometheus / Grafana
- PagerDuty
- AWS Shield Advanced

## 2. Detection Mechanism

### Primary Indicators

The attack is considered a potential P1 when several of the following
conditions occur simultaneously:

```text
API request rate > 10,000 requests/sec
API 5xx rate > 5%
ALB request count increases > 5x baseline
WAF blocked requests > 10,000 requests/minute
Payment API latency P95 > 5 seconds
EKS CPU utilization > 90%
