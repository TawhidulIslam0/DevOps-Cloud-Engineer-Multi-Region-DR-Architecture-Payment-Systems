# RB-07 - DDoS Attack on Payment API

## 1. Scenario Identification
**ID:** S7 | **Category:** Security | **Severity:** P1-Critical | **Components:** ALB, WAF, Shield Advanced, Route 53, EKS, API. Normal peak is 1,200 TPS; attack threshold is 150,000 requests/second.

## 2. Detection Mechanism
Page when request rate exceeds 10,000/s, WAF blocks exceed 10,000/minute, 5xx exceeds 5%, or P95 exceeds 5 seconds.

## 3. Impact Assessment
Classify bot, L7, or volumetric traffic. Protect the 1,200 TPS legitimate capacity, preserve payment idempotency, and quantify affected merchants and blocked requests.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P1 and freeze deployments.
2. **Security (20s):** Run `aws wafv2 get-web-acl --name $env:PAYSECURE_WAF_NAME --scope REGIONAL --id $env:PAYSECURE_WAF_ID --region ap-south-1`.
3. **Network (20s):** Run `aws shield describe-attack --attack-id $env:PAYSECURE_ATTACK_ID --region ap-south-1`.
4. **SRE (20s):** Run `aws cloudwatch get-metric-data --metric-data-queries file://ddos-metrics.json --region ap-south-1`.
5. **App lead (30s):** Enable retry budgets and reject requests without valid idempotency keys.

## 5. Diagnostic Steps (2-5 minutes)
6. **Security (20s):** Inspect WAF sampled requests with `aws wafv2 get-sampled-requests --web-acl-arn $env:PAYSECURE_WAF_ARN --rule-metric-name $env:PAYSECURE_WAF_RULE --scope REGIONAL --time-window StartTime=$env:START,EndTime=$env:END --max-items 100 --region ap-south-1`.
7. **Network (20s):** Confirm ALB target health with `aws elbv2 describe-target-health --target-group-arn $env:PAYSECURE_TARGET_GROUP_ARN --region ap-south-1`.
8. **Platform (20s):** Check `kubectl -n paysecure get hpa,pods`.
9. **SRE (20s):** Compare legitimate merchant traffic with WAF blocked traffic.
10. **IC (20s):** If volumetric, engage Shield; if L7, add a narrow WAF rule; if database saturation exists, shed traffic and invoke RB-12.

## 6. Failover Procedure (5-15 minutes)
11. **Security (30s):** Apply the approved WAF rate rule with `aws wafv2 update-web-acl --name $env:PAYSECURE_WAF_NAME --scope REGIONAL --id $env:PAYSECURE_WAF_ID --default-action file://waf-default.json --rules file://waf-ddos-rules.json --visibility-config file://waf-visibility.json --lock-token $env:PAYSECURE_WAF_LOCK --region ap-south-1`.
12. **IC (30s):** Engage Shield Advanced DRT using the account escalation channel.
13. **Platform (30s):** Scale only validated stateless pods with `kubectl -n paysecure scale deployment/payment-api --replicas=24`.
14. **Network (30s):** Shift approved traffic to Hyderabad only if Mumbai ALB is saturated and DR readiness passes.
15. **IC (30s):** Reopen normal traffic gradually after error rate remains below 0.1% for 5 minutes.

## 7. Communication Protocol
Engineering gets attack class and controls. Management gets legitimate/blocked volume and financial exposure. Merchants receive a service advisory without attacker details. Security/CERT-In notification follows the incident decision.

## 8. Verification and Validation
WAF blocks malicious signatures, legitimate synthetic payment passes, API error rate and P99 return to target, ALB targets remain healthy, and no duplicate transactions appear.

## 9. Rollback Procedure
Remove only the attack-specific WAF rule after traffic normalizes, restore prior HPA replicas, and reverse regional routing only after health validation. Keep evidence and do not delete logs.

## 10. Post-Incident Review
Analyze attack vectors, WAF/Shield evidence, capacity, merchant impact, and rule precision; perform five-whys and update protection tests.
