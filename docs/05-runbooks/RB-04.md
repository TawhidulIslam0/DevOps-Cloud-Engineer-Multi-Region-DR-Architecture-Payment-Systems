# RB-04 — Kafka Cluster Failure

## 1. Scenario Identification

**Runbook ID:** RB-04  
**Scenario:** Kafka Cluster Failure  
**Category:** Infrastructure  
**Severity:** P1 — Critical

### Affected Components

- Amazon MSK Kafka cluster
- Kafka brokers
- Transaction Events topic
- Settlement Triggers topic
- Webhook Deliveries topic
- Audit Log Ingestion topic
- EKS microservices
- Transaction processing services
- Settlement services
- Webhook services
- Consumer groups
- Schema Registry
- ElastiCache
- Aurora PostgreSQL
- DynamoDB
- Monitoring and alerting

### Scenario Description

PaySecure's Amazon MSK Kafka cluster experiences a major failure affecting message production, consumption, broker availability, or replication.

A Kafka failure can prevent transaction events from flowing between PaySecure services and can cause delays in settlement processing, webhook delivery, audit-log ingestion, and downstream transaction processing.

Possible causes include:

- Multiple broker failures
- MSK cluster availability failure
- Network connectivity failure
- Consumer group failure
- Producer failures
- ISR reduction
- Partition unavailability
- Storage exhaustion
- Authentication or authorization failure
- Schema Registry failure
- Regional infrastructure failure

### Recovery Objectives

- **Target RTO:** < 5 minutes
- **Target RPO:** < 1 minute
- **Primary Region:** Mumbai (`ap-south-1`)
- **Recovery Region:** Hyderabad (`ap-south-2`)

## 2. Detection Mechanism

### Primary Detection Signals

| Signal | Threshold | Severity |
|---|---:|---|
| MSK broker unavailable | Any production broker unavailable | P1 |
| Under-replicated partitions | >0 for 2 minutes | P1 |
| Offline partitions | >0 | P1 |
| Consumer lag | >60 seconds | P1 |
| Producer error rate | >5% for 2 minutes | P1 |
| Message processing latency | >30 seconds | P1 |
| Kafka throughput | >20% below baseline | P2 |
| Storage utilization | >80% | P2 |
| ISR count | Below configured replication requirement | P1 |
| Transaction event processing | <99% success | P1 |

### CloudWatch / MSK Monitoring

Monitor:

- `ActiveControllerCount`
- `OfflinePartitionsCount`

- `PartitionCount`
- `BytesInPerSec`
- `BytesOutPerSec`
- `MessagesInPerSec`

- Broker storage utilization
