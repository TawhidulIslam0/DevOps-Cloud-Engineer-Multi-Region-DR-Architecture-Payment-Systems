# RB-04 - Kafka Cluster Failure

## 1. Scenario Identification
**ID:** S4 | **Category:** Infrastructure | **Severity:** P1-Critical | **Components:** MSK, MirrorMaker/Replicator, settlement, webhook, audit consumers. Target service recovery: 15 minutes.

## 2. Detection Mechanism
Page when `UnderReplicatedPartitions > 0`, `OfflinePartitionsCount > 0`, or consumer lag exceeds 10,000 messages for 5 minutes.

## 3. Impact Assessment
At 50,000 messages/second, a five-minute outage can delay up to 15 million events. Settlement and webhooks may be delayed; no direct database bypass is permitted for financial events without DBA approval.

## 4. Immediate Response (0-2 minutes)
1. **IC (15s):** Open P1 and freeze schema/deployments.
2. **SRE (20s):** Run `aws kafka list-clusters-v2 --region ap-south-1`.
3. **SRE (20s):** Run `aws cloudwatch get-metric-data --metric-data-queries file://msk-health-query.json --region ap-south-1`.
4. **Data engineer (30s):** Pause consumers with `kubectl -n paysecure scale deployment settlement-engine --replicas=0`.
5. **App lead (30s):** Keep transaction writes idempotent and record event offsets.

## 5. Diagnostic Steps (2-5 minutes)
6. **SRE (20s):** Run `aws kafka describe-cluster-v2 --cluster-arn $env:PAYSECURE_MSK_ARN --region ap-south-1`.
7. **Data engineer (30s):** Inspect `kubectl -n paysecure get pods -l app=settlement-engine`.
8. **SRE (20s):** Query `aws kafka describe-cluster-operation --cluster-operation-arn $env:PAYSECURE_MSK_OPERATION_ARN`.
9. **Data engineer (30s):** Compare MirrorMaker lag from the monitoring dashboard and checkpoint evidence.
10. **IC (20s):** If brokers are healthy but consumers are lagging, restart consumers; if partitions are offline, use DR replay; if both clusters are unavailable, stop settlement and escalate.

## 6. Failover Procedure (5-15 minutes)
11. **Data engineer (30s):** Confirm DR topics with `aws kafka list-clusters-v2 --region ap-south-2`.
12. **SRE (30s):** Redirect consumer bootstrap configuration to the approved DR cluster and verify the Secret diff.
13. **Platform (30s):** Run `kubectl -n paysecure rollout restart deployment/settlement-engine`.
14. **Data engineer (60s):** Replay only events after the last durable checkpoint; verify idempotency keys before acknowledging each batch.
15. **IC (30s):** If consumer lag falls and no duplicate settlement appears, reopen processing; otherwise pause and invoke reconciliation.

## 7. Communication Protocol
Engineering gets broker/partition/lag status every 10 minutes. Management gets delayed-event count and settlement risk. Merchants receive a delayed-settlement advisory. Regulators receive notice only if settlement SLA or customer funds are affected.

## 8. Verification and Validation
`kubectl rollout status` succeeds; `aws cloudwatch get-metric-data` shows zero offline partitions; consumer lag declines for 5 minutes; one replayed event produces one settlement; audit logs contain offset evidence.

## 9. Rollback Procedure
Scale consumers to zero, restore the previous bootstrap secret, and replay from the last checkpoint. Never delete topics or offsets during an incident. Verify the original cluster before resuming.

## 10. Post-Incident Review
Reconcile every missed event, capture broker metrics and offsets, perform five-whys, review retention and replication, and assign remediation owners.
